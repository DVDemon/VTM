# ADR-002: Холст диаграммы — react-konva (Canvas 2D)

Дата: 2026-05-17

Статус: Accepted

## Контекст

Десктоп VMT рисует диаграмму через `QPainter`/`UICanvas` (см. [`../rendering.md`](../rendering.md)): сетка, прямоугольные узлы с изображениями, Безье-связи, метки условий, мигающая анимация текущего шага, hit-test связей через `QPainterPathStroker`.

В вебе нужно повторить:

- интерактивную сцену с зумом/панорамированием, drag-n-drop узлов;
- кривые Безье на связях с возможностью клика по ним;
- быструю частичную перерисовку (NFR-006: 30+ FPS на 200 узлах / 400 связях);
- экспорт сцены в PNG.

Рассматривались react-konva, PixiJS, SVG+D3, React Flow.

Требования: FR-003, FR-006, FR-007, FR-008, FR-014, FR-019, NFR-006.

## Решение

Используем **react-konva** поверх Konva (Canvas 2D). Сцена строится из 4 слоёв:

1. `background` — фон + сетка;
2. `edges` — связи (`Konva.Path` из кубических Безье);
3. `nodes` — прямоугольники узлов и иконки типов;
4. `overlay` — выделение, drag-preview, анимация текущего шага отладчика.

Слои перерисовываются независимо (`layer.batchDraw()`), `listening` включается только на интерактивных. Для PNG-экспорта используем `stage.toCanvas()` / `OffscreenCanvas` той же сцены.

## Альтернативы

### Альтернатива 1: PixiJS (WebGL)

Быстрее на больших сценах, но избыточен: V1 укладывается в Canvas 2D по метрикам NFR-006. PixiJS требует более сложного управления текстурами, у него меньше готовых рецептов под React-tree и сложнее реализовать pixel-perfect PNG-экспорт, идентичный десктопу.

### Альтернатива 2: SVG + D3

Декларативный DOM, удобный для тестирования, но при 500+ узлах/рёбрах SVG деградирует по производительности; сложно реализовать пиксельный экспорт без оффскрин-канваса; D3 для нашей задачи (готовый редактор) даёт лишнюю абстракцию.

### Альтернатива 3: React Flow

Готовый редактор узлов и связей. Однако:

- свои примитивы маршрутизации, которые сложно заменить на наш порт A* + Безье (ADR-004);
- ограниченные возможности кастомного рендера для иконок узлов и анимации шага;
- jsperf хуже на больших графах;
- зависимость в 100+ KB, неподходящая под NFR-008.

## Последствия

Положительные:

- Canvas 2D-API совпадает по семантике с `QPainter` → лёгкий порт `UICanvas` и `DiagramBezier`.
- Слои дают эффективную локальную перерисовку (аналог dirty-rects из десктопа).
- `stage.toCanvas()` и `toBlob()` решают экспорт в PNG без отдельного рендерера.
- React-konva сохраняет реактивную модель: компоненты узлов получают `props`, перерисовываются по diff.

Отрицательные / компромиссы:

- Hit-test Безье-связей нужно делать вручную (через flatten в полилинию, ADR-004) — Konva не поддерживает stroke-tolerance для `Path` точно.
- На очень больших сценах (1000+ узлов) понадобится переход к WebGL — задел остаётся через тот же `@core` (ADR-002 не влияет на ядро).
- Текст и шрифты в Canvas 2D рендерятся не идентично системному QPainter; нужен фиксированный font-stack (`-apple-system, Inter, sans-serif`), чтобы PNG-экспорт был детерминированным.

## Проверка соблюдения

- В `package.json` присутствуют `konva` и `react-konva`.
- В `src/ui/canvas/` сцена разделена минимум на 4 `<Layer>`.
- Hit-test связей делается через утилиту `isPointNearStroke` из `@core/routing` (ADR-004), а не через Konva-API.
- PNG-экспорт использует ту же сцену (`stage.toCanvas`/`OffscreenCanvas`), а не отдельный рендерер.
- В тестах sceneSize × nodeCount = 200 нет пропадания кадров (FPS ≥ 30) — проверяется Playwright performance-trace.
