# ADR-001: Frontend — Vite + React 18 + TypeScript (SPA)

Дата: 2026-05-17

Статус: Accepted

## Контекст

Десктопное приложение VMT нужно перенести в браузер как полностью клиентский SPA, публикуемый на GitHub Pages. Требуются:

- быстрый dev-цикл, простой бандлинг и поддержка TypeScript «из коробки»;
- зрелая экосистема для UI (тулбары, диалоги, ленивые экраны, локализация);
- размер начального бандла ≤ 350 KB gzip (NFR-008);
- публикация статикой без рантайма SSR.

Рассматривались варианты сборки: Vite, Next.js (static export), Remix SPA Mode.

Требования, влияющие на решение: NFR-001 (GH Pages), NFR-002 (без бэкенда), NFR-008 (размер бандла), NFR-009 (strict TS), NFR-010 (воспроизводимая сборка), FR-001…FR-022 (полный паритет UI).

## Решение

Используем **Vite + React 18 + TypeScript** в strict-режиме. SPA с маршрутизацией через `HashRouter` (см. ADR-007). Сборка через `vite build`, деплой статикой на ветку `gh-pages` GitHub Actions. Линт — ESLint (`@typescript-eslint`, `react-hooks`), форматтер — Prettier. Юнит-тесты — Vitest, e2e — Playwright. Конфиг Vite фиксирует `base: '/VMT/'` и `build.target: 'es2020'`, по экранам включается `import()`-разделение бандла.

## Альтернативы

### Альтернатива 1: Next.js static export

`output: 'export'` даёт SSG, но избыточен: нет серверных страниц, нет ISR, нет API-роутов. Добавляет сложности конфигурации, увеличивает время холодной сборки и размер dev-окружения. Преимущества Next (роутер, image optimization) для V1 не нужны.

### Альтернатива 2: Remix SPA Mode

Перспективная схема, но менее зрелая экосистема плагинов и меньше готовых рецептов под GitHub Pages. Не даёт ощутимых выгод по сравнению с Vite для чистого SPA.

### Альтернатива 3: Create React App / Webpack

Устарел, медленный dev-сервер, отсутствует ESM-first подход. Не рассматривается.

## Последствия

Положительные:

- Быстрый HMR, типизация, минимальный конфиг.
- Лёгкий деплой статикой на GH Pages.
- Большое сообщество и шаблоны под Vitest/Playwright.
- Простое code-splitting через динамический `import()`.

Отрицательные / компромиссы:

- Нет SSR/SSG для SEO (нерелевантно для приложения-инструмента).
- Vite-специфичные плагины при миграции на другой бандлер придётся пересмотреть.
- Необходимо настраивать `base` под путь GH Pages и `HashRouter` для глубоких ссылок.

## Проверка соблюдения

- В `package.json` присутствует `vite`, `react@18`, `typescript`; `tsconfig.json` имеет `"strict": true`.
- `vite.config.ts` содержит `base: '/VMT/'`.
- В CI есть шаги `lint`, `test`, `build`, `deploy` на `gh-pages`.
- Стартовый бандл проверяется в CI (`vite build` + `rollup-plugin-visualizer` или `size-limit`) и не превышает 350 KB gzip.
- В исходниках нет файлов с расширением `.jsx`/`.js` в `src/` (только `.ts`/`.tsx`).
