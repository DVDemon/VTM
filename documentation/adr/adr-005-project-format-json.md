# ADR-005: Формат проекта — JSON v1 + обмен `.jdtp` через локальный файловый диалог

Дата: 2026-05-17

Статус: Accepted

## Контекст

Десктоп VMT сохраняет проект в бинарном `.jdtp` через `QDataStream` (см. [`../data-formats.md`](../data-formats.md)). Два формата узлов: v1 (legacy) и v2 (текущий). Для веб-версии нужно:

- иметь компактное представление черновика в браузере — строка `.vmt.json` в localStorage при необходимости (ADR-003), без размещения бинарных blob `.jdtp` в key-value-хранилище браузера;
- иметь читабельный экспорт для Git — `.vmt.json`;
- **полная совместимость с десктопом по файлам `.jdtp`**: пользователь открывает файл с локального диска и сохраняет диаграмму обратно на диск как `.jdtp` (как в Qt `QFileDialog`), без загрузки на сервер приложения;
- иметь стабильную JSON-схему с миграциями (NFR-005).

Требования: FR-001, FR-020, FR-023, NFR-002, NFR-005, NFR-010.

## Решение

1. **Нативный формат в памяти и для экспорта на Git** — **JSON v1** (`schemaVersion: 1`), UTF-8, расширение `.vmt.json`. Опционально сохраняется как строка в localStorage (ADR-003) или скачивается файлом.

2. **Файлы `.jdtp`** — не являются источником истины в браузерном хранилище. Импорт: пользователь выбирает файл (`<input type="file">` или Drag-and-drop на область приложения); приложение читает `ArrayBuffer` и парсит поток идентично десктопному сериализатору (big-endian `QDataStream`). Экспорт: ядро сериализует текущий `Project` в `ArrayBuffer`; UI инициирует скачивание (`<a download>` с `Blob`) или **File System Access API** `showSaveFilePicker()` там, где поддерживается.

3. Модуль `@core/serializer/jdtp-io.ts` содержит **чтение и запись** бинарного формата v1+v2 узлов (порт логики `VMTSerializer.cpp`). Отдельный read-only режим не требуется.

Схема JSON:

```jsonc
{
  "schemaVersion": 1,
  "id": "uuid",
  "name": "My Machine",
  "alphabet": " 01",
  "machines": [ /* ComplexMachine[] */ ],
  "createdAt": "2026-05-17T10:00:00Z",
  "updatedAt": "2026-05-17T10:00:00Z"
}
```

Миграции JSON — массив функций `migrate[v]: (data) => data`.

## Альтернативы

### Альтернатива 1: Хранить `.jdtp` в IndexedDB как основной источник

Позволяет держать большие проекты локально без файлового диалога. Минусы: поведение расходится с десктопом («Сохранить» = файл на диске); усложняет UX для пользователя, привыкшего к `.jdtp`-файлам; усложняет резервное копирование (нет явного файла). Отклонено для V1 в пользу явного файлового обмена.

### Альтернатива 2: Только импорт `.jdtp`, экспорт только `.vmt.json`

Ломает паритет FR-023 и перенос проектов обратно в десктоп без конвертации. Отклонено.

### Альтернатива 3: Свой бинарный формат вместо JSON

Не нужен: JSON достаточен для черновиков и Git; `.jdtp` уже задан десктопом.

## Последствия

Положительные:

- Поведение «открыть / сохранить файл» совпадает с ментальной моделью десктопного приложения.
- Нет загрузки содержимого диаграмм на сервер; данные остаются у пользователя.
- Совместимость с существующими учебными материалами в `.jdtp`.

Отрицательные / компромиссы:

- Safari/Firefox могут не поддерживать File System Access API — fallback только на `<a download>` с именем по умолчанию.
- Дублирование логики сериализации C++ ↔ TS должно поддерживаться тестами byte-level round-trip.

## Проверка соблюдения

- В `src/core/serializer/json.ts` есть `serializeProject` / `deserializeProject` + цепочка миграций.
- В `src/core/serializer/jdtp-io.ts` есть `decodeJdtp(buffer: ArrayBuffer): Project` и `encodeJdtp(project: Project): ArrayBuffer`.
- В UI нет вызова сервера для сохранения `.jdtp`; нет `localStorage.setItem` для бинарного содержимого `.jdtp`.
- Тесты: round-trip `encodeJdtp(decodeJdtp(fixture))` совпадает с эталонным буфером (или семантически эквивалентен после канонизации).
- Юнит-тест round-trip JSON: `deserializeProject(serializeProject(p)) ≡ p`.
