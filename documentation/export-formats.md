# 4. Форматы экспорта

[← Назад к оглавлению](index.md)

VTM поддерживает три формата экспорта диаграммы текущей машины: PNG, PlantUML и «четвёрки» (текстовая нотация переходов).

## 4.1. PNG

Точка входа: кнопка `button_export` → `FormEditorMachine::ExportMachine()`.

Алгоритм:

1. `QFileDialog` для выбора имени файла (фильтр `*.png`).
2. Берётся прямоугольник `GetBoundsWithChilds()` корневой комплексной машины + отступы по 20 px.
3. Создаётся `QImage(QSize(w,h), QImage::Format_ARGB32)`.
4. На созданном `UICanvas` (тот же класс, что в редакторе) рисуется диаграмма: фон, сетка, узлы, переходы (Bézier).
5. `QImageWriter` сохраняет файл; при необходимости автоматически добавляется расширение `.png`.

Изображение получается **«как на экране»**: те же цвета, шрифты, кривые линии, метки переходов. Видимая область определяется bounding-box диаграммы, а не текущим viewport.

## 4.2. PlantUML (`.puml`)

Точка входа: кнопка `button_export_plantuml` → `FormEditorMachine::ExportPlantUml()` → `VmtExportPlantUml::exportStateMachine()` (`vmtexportplantuml/vmtexportplantuml.cpp`).

### Структура файла

```plantuml
@startuml
!theme plain
hide empty description
skinparam shadowing false
skinparam state {
  BackgroundColor White
  BorderColor #212121
}

title <Имя машины>

state "<display name>" as <alias> {
   ... вложенные state ...
}

state "<display name>" as <alias>
[*]   --> <alias>     : <условие>
<a>   --> <b>         : <условие>
<b>   --> [*]         : *
@enduml
```

### Правила преобразования

| Элемент VTM | PlantUML |
|---|---|
| `VMTComplexMachine` (вложенная) | `state "..." as alias { ... }` рекурсивно |
| Простая машина (Left/Right/.../Write/Copy) | `state "..." as alias` |
| `MT_START`, `MT_FINISH` | `[*]` (стартовая/финальная точка) |
| `MT_WRITE` (`VMTMachineAlpha`) | `state "λ(<символ>)"` |
| Переход | `from --> to : <label>` |
| Условие «все символы алфавита» | `: *` |
| Пустое условие | `: ε` |
| Прочее | `: <строка включённых символов>` |

### Алиасы

Имя машины очищается до `[A-Za-z0-9_]` (`sanitizeAliasBase`). При совпадении добавляется суффикс `_2`, `_3` (`makeUniqueAlias`). В PlantUML экранируются `\`, `"`, переводы строк.

## 4.3. Четвёрки

Точка входа: кнопка `button_4th` → `UIStateExport4th` / `FormExport4th` → `VMTExport4th::Export(callback, environment)`.

Класс `VMTExport4th` (`vmtexport4th/vmtexport4th.cpp`) формирует развёрнутую программу машины Тьюринга в виде последовательности **четвёрок** (или **пятёрок** — формат настраивается параметрами):

```
state | "char" | command | next_state
```

или для записывающих машин:

```
state | "char" | "write" | next_state
```

где `command ∈ {left, right, stop}`. Разделитель (`_delimiter`), кавычки (`_quotes`) и обозначения движений (`_left`, `_right`, `_stop`) задаются пользователем при экспорте — это позволяет получать привычные нотации (`q0, '0', R, q1`, табличные форматы и т. д.).

### Алгоритм

1. **Проверка на рекурсию.** `MachineFunction` обходит все вложенные комплексные машины; если имя машины уже в стеке вызовов — выдаётся ошибка («Recursive machine call»).
2. **Нумерация состояний.** `MapState()` рекурсивно проходит дерево, присваивая каждому узлу глобальный индекс. Для составных машин-«сахар» (`MT_LEFT_WORD`, `MT_RIGHT_WORD`, `MT_COPY`) вызывается `CreateComplexMachine()`, и их внутренние состояния тоже получают номера.
3. **Генерация переходов.** `ProcessComplex()` от стартового узла обходит граф и для каждого исходящего перехода формирует строку формата `FormatString(state, char, cmd, state2)`. Состояния FINISH верхнего уровня замыкаются на самих себя для каждого символа (`stop`).
4. Экспорт идёт в фоновом потоке `std::thread`; результат поступает в `TextCallback::AppendText`. Прогресс/информация — `Information(...)`; завершение — `Done()`.

### Особенности

- Поддерживаются произвольные алфавиты (включая λ — первый символ строки алфавита).
- Учитывается множитель `power` каждой машины — состояния «размножаются» в стеке вызовов.
- Сложные машины (`MT_COMPLEX`) инлайнятся: каждый вызов добавляет в нумерацию полное поддерево.
- Рекурсия не поддерживается; экспорт прерывается с ошибкой.

### Применение

Готовый текст можно сохранить и подать на внешний интерпретатор машины Тьюринга (например, при сдаче лабораторных работ в нотации Поста/Тьюринга).
